# RIOTX Workbench 사용 가이드

## 1. 접속과 화면 구성

배포 후 로컬은 `http://127.0.0.1:8088`, AWS는 인증서와 연결한 HTTPS 도메인으로 접속합니다. 접근 토큰이 설정되어 있으면 입력 창에 `WORKBENCH_TOKEN` 값을 입력합니다. 토큰은 브라우저 sessionStorage에 저장되며 별도의 사용자 계정 시스템은 아닙니다.

- **좌측**: 업무 작업공간과 작업 목록, 새 작업, 실행 이력 서랍
- **중앙**: 선택한 작업의 흐름, 입력 수·타깃 키 수, 관측 이벤트와 활동
- **우측 서랍**: 모니터·설정·로그·소개. 접으면 중앙 화면이 넓어집니다.
- **상단 전체 설정**: System match(기본) 또는 Dark. 선택은 이 브라우저 전체에 저장됩니다.

좌측 하단의 실행 이력을 클릭하면 위로 펼쳐집니다. 실행을 선택하면 그 실행의 로그가 열립니다. 긴 목록은 내부에서 스크롤하고, 다시 클릭하거나 서랍 안에서 Esc를 눌러 접습니다. 모바일에서는 화면 하단에 표시합니다.

## 2. Redis 연결 등록

1. 상단 **연결 관리 → 연결 추가**를 누릅니다.
2. 이름과 `redis://host:6379/0` 또는 TLS용 `rediss://host:6379/0`을 입력합니다.
3. 사용자 이름과 비밀번호는 URL에 넣지 말고 별도 필드에 입력합니다.
4. Cluster 여부·활동 구독·키 이름 마스킹을 선택하고 저장합니다.

Docker에서 `localhost`는 Workbench 컨테이너 자신입니다. 데모 Redis는 `redis://source:6379/0`, `redis://target:6379/0`을 사용합니다. 운영 Compose에는 이 서비스들이 없으므로 실제 Redis DNS나 접속 가능한 주소를 등록합니다. ECS에서는 호스트 VPC에서 Redis까지의 라우팅·보안 그룹·TLS·ACL을 확인합니다.

## 3. 데이터 이전 작업 생성

1. **새 작업**을 누르고 이름·업무 작업공간·작업 유형을 선택합니다.
2. 소스·타깃 연결과 필요한 옵션을 선택합니다.
3. 저장 후 **설정 검증**으로 포함 RIOTX가 지원하는 명령·옵션을 확인합니다.
4. **실행**을 누르고 모니터·로그에서 진행을 확인합니다.

설정 검증은 실행 결과 보장이 아닙니다. SQL·SpEL, 실제 쓰기와 외부 시스템 연결은 실행 시 검증됩니다. 같은 타깃 DB에 동시에 쓰는 실행은 보수적으로 차단됩니다. 취소해도 이미 기록한 데이터는 남을 수 있습니다.

수정한 설정은 다음 실행에 적용됩니다. 기존 실행의 설정 사본은 바뀌지 않습니다. 다른 실행을 선택했을 때 현재 실행과 과거 로그를 혼동하지 않도록 실행 ID를 확인하세요.

## 4. 실시간 복제와 알림

복제 모드의 SCAN은 초기 복사를, LIVE는 초기 복사와 이후 알림 기반 처리를 수행합니다. LIVE/LIVEONLY는 소스의 keyspace notifications가 필요합니다.

**설정**에서 양쪽 알림 탐지 상태를 확인합니다.

| 항목 | 동작 |
| --- | --- |
| 활동 구독 | Workbench의 관측 연결만 켜거나 끕니다. |
| 서버 설정 변경 허용 | 명시적인 Redis CONFIG 변경을 허용합니다. |
| 서버 알림 활성화 → Redis에 적용 | 켜기는 기존 플래그에 KEA를 추가하고, 끄기는 전체 알림을 비활성화합니다. |
| 확인 불가 | CONFIG 권한이나 연결 상태를 확인합니다. 비활성이라고 단정하지 않습니다. |

서버 알림 변경은 해당 DB가 아니라 Redis 서버 전체에 영향을 줍니다. 운영 서버에서는 DBA와 적용 범위를 확인하세요. CONFIG REWRITE는 자동 실행하지 않습니다. 관리형 Redis에서는 파라미터 그룹 등 서비스의 설정 절차가 필요할 수 있습니다.

상단 Redis 키 수는 선택한 DB 전체의 키 수이며 `key-pattern`에 해당하는 키만 센 값이 아닙니다. 2초 간격의 개별 조회이므로 소스·타깃이 완전히 같은 시점의 값은 아닙니다. 활동 그래프는 관측된 알림 수이며 RIOTX의 전송 처리량과 다를 수 있습니다.

## 5. 결과 비교

복제를 선택한 뒤 하위 **결과 비교**로 이동합니다. 연결과 비교 범위는 상위 복제의 현재 설정을 참조합니다.

- QUICK: 타입·TTL 중심 비교
- FULL: 값까지 비교
- NONE: 상위 설정에서 비교 실행 차단

비교는 독립된 실행·이력을 갖습니다. LIVE 중 변경되는 데이터는 순간적인 차이가 발생할 수 있습니다. 최종 판정은 비교 범위와 실제 RIOTX 로그를 확인하세요. 동일 키 수와 exit 0은 전체 데이터 일치의 증명이 아닙니다.

## 6. 파일 가져오기와 교체 감시

1. 파일 가져오기 작업을 만들고 입력 파일을 업로드하거나 기존 파일을 선택합니다.
2. 옵션 JSON에서 실제 파일의 `type`을 설정합니다. CSV 예: `{"type":"csv","header":true,"batch":50}`. JSON 배열 예: `{"type":"json","batch":50}`.
3. Redis 쓰기 명령과 키 템플릿을 설정합니다. 예: HSET, `record:#{id}`. JSON.SET은 타깃의 해당 명령 지원 여부를 확인합니다.
4. 먼저 수동 실행하여 입력 형식과 결과를 확인합니다.
5. 설정의 **파일 교체 시 자동 가져오기**를 켜면 이후 파일 교체를 감지해 다시 import합니다.

파일 소스는 해당 입력의 **원본 레코드 수**를 표시합니다. CSV는 헤더 등을 제외하며 JSON 배열/객체·JSONL도 지원합니다. 필터·최대 처리 수·중복 키에 따른 최종 Redis 키 수와는 다릅니다. 집계 미지원 형식이나 파서 설정은 `—`와 설명으로 표시합니다.

서버는 2초마다 inode·크기·mtime/ctime 등의 메타데이터를 비교합니다. 동일 파일은 내용을 다시 읽지 않습니다. 변경이 안정되면 버전 사본을 만들고 집계·실행하며, 실행 중 변경은 해당 실행이 끝난 뒤 처리합니다. 같은 버전의 실패·취소는 자동 반복하지 않으므로 로그 확인 후 수동 재실행하거나 새 파일로 교체하세요.

**설정 → 입력 파일 교체**는 서버에 저장된 파일을 교체합니다. PC에서 처음 선택한 원본 파일을 수정하는 것만으로는 서버가 감지할 수 없습니다. 동일한 서버 파일을 참조하는 작업 모두에 교체가 적용됩니다. 자동 가져오기를 꺼도 변경 확인과 집계 갱신은 계속됩니다.

## 7. 로그·삭제·업데이트

- 실행 이력에서 ID를 선택하고 로그 검색·레벨 필터로 확인합니다. 최근 실행당 2,000줄을 보관합니다.
- 작업/작업공간의 옵션 메뉴에서 삭제할 수 있습니다. 실행 중이면 삭제가 차단됩니다. 상위 복제 삭제에는 하위 비교가 포함됩니다.
- **삭제한 항목**에서 복원합니다. Redis 데이터·연결 프로필·과거 로그는 삭제하지 않습니다.
- **소개**는 포함/최소 지원 RIOTX, 의존성, 공식 안정 버전을 표시합니다. 새 바이너리를 실행 중 자동 교체하지 않습니다.

## 8. 자주 발생하는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| 키 수가 `—` 또는 갱신 지연 | 주소, 네트워크, 인증·ACL, Cluster primary 접근 가능 여부 |
| LIVE 시작 거부 | 소스 알림 KEA와 CONFIG 조회 권한, 같은 소스·타깃인지 |
| AWS에서 UI 502/503 | ECS 이벤트, EC2 등록, EBS 마운트, 타깃 헬스체크, CloudWatch 로그 |
| 연결 URL은 맞는데 Docker 접속 실패 | localhost의 의미, 컨테이너 DNS, 방화벽과 TLS |
| 재시작 뒤 UNKNOWN 실행 | 실행 중 프로세스는 자동 재개하지 않습니다. 기존 쓰기 결과를 확인한 뒤 새 실행을 시작합니다. |
| 파일 교체 후 재실행 안 됨 | 첫 수동 실행 여부, 토글, 기존 실행·타깃 충돌, 파일 권한, 로그 |

배포 문제는 [Docker](DEPLOY_DOCKER_KO.md), [AWS ECS](DEPLOY_ECS_KO.md), 운영 원칙은 [가이드라인](GUIDELINES_KO.md)을 참고하세요.

## 연결 프로필 삭제

상단 **연결 관리 → 프로필 오른쪽 ⋮ → 연결 삭제**에서 영향을 받는 작업을 확인한 뒤 삭제합니다. 데모 소스와 데모 타깃도 같은 메뉴를 사용하며, 사용자가 삭제하기 전에는 유지됩니다.

- 해당 연결을 사용하는 대기·실행 중 작업이 있으면 삭제가 거부됩니다.
- 연결 프로필과 저장된 인증 정보는 영구 삭제됩니다. 작업(삭제한 작업 포함)의 해당 연결 지정이 해제되므로, 다시 실행하려면 작업 설정에서 연결을 선택해야 합니다.
- 실행 이력·로그와 Redis 서버의 데이터는 보존됩니다. 이 기능으로 Redis 서버나 컨테이너를 삭제하지 않습니다.
