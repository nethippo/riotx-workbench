# 한국어 운영 가이드라인

RIOTX Workbench는 신뢰하는 운영자가 사용하는 데이터 이전 도구입니다. 기본 애플리케이션은 단일 서버·단일 SQLite 저장소를 전제로 합니다.

## 1. 환경 분리

- 데모, 검증, 실제 업무의 Redis 연결·키 접두사·배포 볼륨을 구분합니다.
- 운영 Redis 전체에 FLUSHDB/FLUSHALL을 실행하지 않습니다. 테스트 데이터 정리는 생성한 접두사의 범위를 확인합니다.
- `tests/integration.py`와 TTL 생성기는 실제 데이터/설정을 변경하므로 독립된 데모 환경에서만 사용합니다.
- Docker 운영 Compose는 DEMO_ENABLED=false입니다. ECS도 테스트 Redis와 데모 잡을 자동 생성하지 않습니다.

## 2. 인증·접근·비밀값

- 외부 접속은 HTTPS와 네트워크 접근 제한을 함께 사용합니다. 애플리케이션 토큰은 개인별 RBAC를 대체하지 않습니다.
- Docker 토큰은 Git에서 제외된 0600 `.env`, ECS 토큰은 Secrets Manager에 보관합니다.
- Redis 사용자/비밀번호를 URI·옵션 JSON·문서·GitHub 이슈에 적지 않습니다. UI의 별도 필드에 입력합니다.
- `.env`, `secret.key`, SQLite, Terraform state/plan, 실제 `.tfvars`, 이미지 생성 JSON을 커밋하지 않습니다.
- Terraform state에는 리소스·환경 정보가 들어갑니다. 공유 운영은 암호화·접근 제어·잠금이 있는 별도 backend를 사용합니다.
- AWS 자격 증명은 SSO/역할 등 조직 정책에 맞게 관리합니다. 배포용 운영자와 ECS 실행 역할/태스크 역할을 구분합니다.
- API/컨테이너/클라우드 로그는 인증 정보가 포함되지 않았는지 확인한 뒤 공유합니다. Docker inspect나 compose config도 비밀값을 보여줄 수 있습니다.

## 3. 실행 전 확인

1. 소스/타깃과 DB 번호가 의도한 환경인지 확인합니다.
2. 쓰기 범위·키 템플릿·필터·TTL 처리·덮어쓰기 동작을 샘플 범위로 확인합니다.
3. 타깃 백업과 롤백 방법을 준비합니다. 프로세스를 취소한다고 이미 쓴 데이터가 되돌아가지는 않습니다.
4. LIVE는 소스 알림 상태와 알림 누락 위험을 확인합니다. 타깃 알림은 별도 관측입니다.
5. 초기 데이터 복사 이후 비교 범위와 완료 기준을 정합니다.

같은 타깃의 동시 쓰기는 기본 차단합니다. 여러 JVM 프로세스를 실행할 때는 데이터 크기와 CPU/메모리를 확인합니다. 운영 배포의 기본 동시 실행 수는 1이며 의도적으로 늘립니다.

## 4. 알림과 지표 해석

- 소스·타깃 키 수는 각각 조회한 DB 전체 합계입니다. 특정 패턴의 복제 완료율이 아닙니다.
- Pub/Sub는 영속 감사 로그가 아니며 재연결 중 활동이 누락될 수 있습니다.
- 알림 그래프와 RIOTX 메트릭을 구분합니다. 키 수가 같거나 프로세스 exit 0이어도 데이터가 모두 같다고 판정하지 않습니다.
- 결과 비교는 상위 복제 설정을 참조합니다. 동시 변경이 있는 LIVE에서 비교한 결과는 동일 시점의 원자적 스냅샷이 아닙니다.
- 알림을 켜거나 끄는 CONFIG 변경은 서버 전체에 영향을 줍니다. 기존 설정·다른 업무의 구독을 확인하고 적용합니다.

## 5. 파일과 자동 실행

- 브라우저 원본 파일과 서버 업로드 사본을 구분합니다. 서버는 PC의 원본 변경을 직접 볼 수 없습니다.
- 동일 서버 파일을 여러 작업이 참조하면 교체가 모두에 적용됩니다.
- 첫 수동 실행 후 자동 가져오기를 활성화합니다. 업데이트·점검 전에는 자동 실행을 꺼 예상하지 않은 쓰기를 막습니다.
- 메타데이터 감지는 콘텐츠 해시 검증이 아닙니다. 같은 내용도 파일 교체/수정 시각 변경에 따라 새 버전으로 처리할 수 있습니다.
- `/data/files/versions`의 사본은 실행 입력 재현을 위해 남습니다. 볼륨 용량을 모니터링합니다. 실행 이력이 참조하는 버전을 임의로 삭제하지 마세요.

## 6. 영속성·백업

- `/data` 전체를 함께 보존합니다. SQLite만 복사하고 `secret.key`를 잃으면 연결 프로필을 복호화할 수 없습니다.
- WAL 모드 SQLite를 EFS/NFS로 옮기거나 서로 다른 Workbench 태스크에서 동시에 열지 않습니다.
- 앱·잡을 정상 종료한 뒤 일관된 볼륨 백업/EBS 스냅샷을 만듭니다. 원본 Redis는 별도로 백업합니다.
- 복원은 격리된 볼륨/환경에서 검증하고 실제 Redis 자동 재실행 여부부터 확인합니다.
- Docker `down -v`, EBS 삭제, state 삭제를 일상적인 재배포 절차로 사용하지 않습니다.

## 7. 배포·업데이트·장애

- Git 커밋, 이미지 digest, Terraform plan, 적용 시간과 담당자를 기록합니다.
- Terraform plan에서 EC2 교체·EBS 재연결·보안 그룹 변경을 확인합니다. EBS의 prevent_destroy를 편의상 해제하지 않습니다.
- ECS는 단일 태스크를 stop-first로 교체합니다. 배포 전 잡을 종료하고 중단 창을 확보합니다.
- 컨테이너 종료 후 UNKNOWN 실행은 자동 재개하지 않습니다. 실제 기록된 범위를 확인하고 수동으로 다시 실행합니다.
- ECS 호스트 AMI 패치는 명시적인 유지보수 절차로 처리합니다. 현재 구성은 무중단/다중 AZ 자동 복구를 제공하지 않습니다.
- RIOTX는 공식 redis/riotx-dist의 안정 릴리스와 체크섬을 확인하고 테스트한 후 이미지를 재빌드합니다. 라이선스·최소 지원 버전·명령 옵션 변화도 검토합니다.
- Secret 회전은 태스크 교체 이후에 반영됩니다. 기존 UI 세션의 토큰도 갱신합니다.

## 8. 개발·변경 검증

- 프런트엔드 동작은 실제 화면에서 테마·서랍·키 수·저장/새로고침을 확인합니다.
- 백엔드 단위 테스트는 임시 SQLite/파일을 사용합니다. 사용 중인 Redis를 대상으로 테스트를 실행하지 않습니다.
- 배포 변경은 `scripts/deploy/validate.sh`로 문법·Compose·Terraform과 mock plan을 검사합니다.
- `terraform validate`/mock test 통과와 실제 AWS 배포 성공을 구분하여 보고합니다.
- 배포 스크립트는 plan과 apply를 분리합니다. saved plan은 설정 변경 후 다시 생성합니다.
- 커밋 전 `git diff --check`와 추적 파일 목록을 확인하고, push 후 로컬/원격 SHA 일치를 확인합니다.
