# MongoDB 가져오기와 Enterprise 중복 검사

2026-11-16 구현 기준입니다. 기존 RIOTX CLI 작업과, 키별 감사 기록을 남기는 Workbench 관리형 작업을 구분합니다.

## 연결과 실행 순서

1. **연결 관리**에서 소스 Redis 또는 MongoDB 프로필을 만듭니다. Redis 프로토콜 주소는 `redis://` 또는 TLS의 `rediss://`입니다. HTTP URL은 Redis 접속 주소가 아닙니다.
2. 타깃 제품을 **Redis Enterprise Software**로 선택하면 **Proxy endpoint**, **Bloom 사전 검사**가 기본 선택됩니다. OSS Cluster API를 노출하는 배포에서만 Cluster를 명시적으로 선택하세요. Software 제품 버전과 `INFO`에 나오는 Redis 엔진 버전은 별개입니다.
3. **전체 설정 → 가져오기와 중복 검사 기본값**에서 용량, 오탐률, 분할 크기, 단일 문서·키 크기, 감사 보존 기간을 저장합니다. 설정은 실행 제출 시 고정됩니다.
4. 작업의 기존 키 정책을 선택하고 실행합니다. **기존 RIOTX 실행**은 원래 CLI 동작을 유지하며 키별 감사 기록이 없습니다. **소스 기준 갱신·중복 관찰**은 값을 갱신하면서 중복을 기록합니다. **기존 키 유지**는 SCAN·MongoDB 일괄 처리에서 기존 값을 보존합니다.
5. 중앙 **중복 키 대시보드**에서 고유 키 수와 확인 횟수를 구분해서 보고, **이벤트 보기**로 우측 로그 서랍의 해당 이벤트를 확인합니다.

이번 로컬 배포는 호스트의 `redis://localhost:6379/0`을 소스로 사용합니다. Docker에서는 같은 서버를 `redis://host.docker.internal:6379/0`으로 연결합니다. Linux Docker에서는 호스트 주소 또는 `host-gateway` 매핑이 별도로 필요합니다. 실제 주소·인증정보는 프로필/로컬 환경에 보관하고 이미지나 공개 예시에 고정하지 않습니다.

## Bloom과 정확한 쓰기

Bloom은 최적화를 위한 힌트입니다. 필터에 없더라도 타깃에 이미 키가 있을 수 있습니다. 양성이더라도 실제 키가 없으면 반드시 기록합니다. 필터 생성·조회가 실패하면 정확한 검사로 대체하고 대시보드에 대체 상태를 표시합니다. 서버 모듈 설치나 자동 설정 변경은 하지 않습니다.

Redis Proxy를 통해 단일 데이터 키에 대한 Lua 쓰기를 수행합니다. `EXISTS`와 `RESTORE REPLACE` 또는 JSON/String 쓰기를 같은 스크립트로 실행하여 다른 작성자와의 경쟁에서도 기존 키 유지 정책을 지킵니다. Bloom 메타데이터는 별도 명령으로 성공한 쓰기/존재 확인 뒤 갱신합니다. 필터와 데이터가 한 트랜잭션에 있다고 가정하지 않습니다. 연결 단절로 응답을 받지 못하면 성공/실패로 단정하지 않고 **결과 불명**으로 기록합니다.

필터는 타깃 URL과 키 범위로 구분한 `wb:dedup:` 예약 접두사를 사용하며 복제 대상에서 제외합니다. 예약 메타데이터도 타깃 DB 전체 키 수에 포함됩니다. 필터는 작업 간 재사용되며 자동 삭제하지 않습니다. Active-Active 타깃의 관리형 쓰기는 지원하지 않습니다.

## Redis → Redis

관리형 복제는 SCAN으로 순회하고 DUMP/RESTORE로 자료형과 TTL을 보존합니다. 현재 키 단위 순차 처리이며 단일 키 최대 크기를 적용합니다. `struct`와 일부 CLI 옵션은 지원하지 않습니다. 큰 자료구조의 분할 처리 또는 CLI 고유 기능이 필요하면 기본 RIOTX 실행을 사용하세요. 관리형 복제의 배치·스레드 옵션은 처리 병렬도를 조절하지 않습니다.

LIVE/LIVEONLY는 **중복 관찰·갱신**만 허용합니다. 기존 키를 건너뛰면 변경사항이 전달되지 않기 때문입니다. 소스 알림이 필요하며 실행 전 탐지합니다. 구독을 먼저 연 뒤 초기 SCAN을 수행합니다. 값·TTL 변경과 삭제를 반영하지만 Pub/Sub는 내구성 있는 변경 로그가 아니므로 연결 단절 시 이벤트가 누락될 수 있습니다. 구독 실패 시 작업을 실패로 종료합니다. 재연결·전체 재스캔과 결과 비교는 운영자가 판단해야 하며 정확히 한 번 처리나 무손실 CDC를 보장하지 않습니다.

## MongoDB 일괄 가져오기

- 연결 제품을 MongoDB로 선택하고 `mongodb://` 또는 `mongodb+srv://` URI를 입력합니다. 계정·비밀번호는 별도 필드로 입력합니다. 읽기 가능한 실제 MongoDB를 별도로 등록해야 합니다.
- 작업 유형은 **MongoDB 일괄 가져오기**입니다. 데이터베이스·컬렉션, JSON 조회 필터, 필드 목록, Redis 키 접두사, JSON/String, BSON 변환, TTL을 지정합니다. JSON 저장에는 타깃 JSON 명령 지원이 필요합니다.
- 기본값은 Canonical Extended JSON이며 ObjectId·날짜·Decimal128 등의 BSON 타입 정보를 보존합니다. Relaxed 모드는 숫자 타입 정보 일부가 생략될 수 있습니다.
- `_id`의 Canonical BSON 표현을 URL-safe Base64로 바꿔 키 접두사 뒤에 붙입니다. ObjectId와 같은 글자의 String, 숫자와 String을 서로 다른 키로 매핑합니다.
- 정렬된 커서로 읽어 JSONL 청크를 만듭니다. 기본 목표 32MiB, 최대 문서 64MiB입니다. 변환 후 JSON 크기를 제한하며, 한 문서가 청크 목표보다 크면 단독 청크가 됩니다. 파일 전체를 메모리에 적재하지 않습니다. 미처리 파일은 최대 2개, 추가로 생성 중인 메모리 버퍼 1개를 허용합니다.
- `/data/ingest/<run-id>/manifest.json`에 조회 체크포인트, 파일 체크섬, 진행 위치를 저장합니다. 성공한 파일은 지우며 디스크 공간이 부족하면 중단합니다. 파일 임시 데이터는 암호화되지 않으므로 볼륨 접근을 제한하고 운영 디스크 암호화를 사용하세요.
- 실패·취소 후 작업 설정과 연결 URL을 유지한 채 **체크포인트에서 재개**합니다. 마지막 체크포인트 이후 일부 문서는 다시 처리할 수 있습니다. 감사 기록의 중복 횟수에는 재개 시 재처리도 포함됩니다. 실패한 실행의 파일은 재개를 위해 남습니다. 다시 필요 없는 중단 작업 파일은 백업·보존 정책에 따라 별도로 정리하세요.
- 재개 가능한 `_id` 순회는 컬렉션 내 동일 BSON 타입을 요구합니다. 혼합 타입이면 오류로 중단합니다. 실행 중 원본 변경은 제한하세요. 동일 시점 스냅샷, MongoDB Change Streams CDC, 자동 스케줄링은 제공하지 않습니다.

소스 문서 수는 실행 시작 시 같은 조회 필터로 집계합니다. 집계 권한·시간 제한으로 확인하지 못하면 미확인으로 표시합니다. Redis DB 키 수로 대신 표시하지 않습니다.

## 감사 기록과 키 이름

실제 존재를 확인한 경우만 중복으로 집계합니다. 같은 키를 여러 번 처리하면 확인 횟수는 증가하고 고유 키 수는 유지됩니다. 값의 동일성을 뜻하지 않습니다. 비교는 별도 메뉴에서 실행하세요.

키 이름은 기본 마스킹합니다. **전체 설정의 키 이름 보관**을 켜고 **타깃 프로필의 키 마스킹**을 꺼야 새 실행의 키 이름을 기록합니다. 원문 이름은 Fernet으로 암호화해 SQLite에 저장하며 별도의 HMAC 식별자로 고유 수를 계산합니다. 상세 이벤트/암호화 이름은 설정한 기간 후 조회·실행 시 정리됩니다. 고유 수 계산용 해시와 누적 카운터는 유지합니다. 일반 프로세스 로그 2,000줄 제한과 독립적입니다. SQLite·암호화 키·청크를 포함한 `/data` 전체를 함께 백업하세요.

## API

| 경로 | 용도 |
| --- | --- |
| `GET/PUT /api/ingest/defaults` | 전체 가져오기 기본값 |
| `GET /api/runs/{id}/audit/summary` | 집계 및 Bloom/청크 상태 |
| `GET /api/runs/{id}/audit/keys?after=0&limit=50` | 중복 키 커서 목록 |
| `GET /api/runs/{id}/audit/events?event_id=…` | 키별 이벤트 연결 |
| `GET /api/runs/{id}/audit/events?latest=true` | 최신 이벤트 우선 |
| `POST /api/runs/{id}/resume` | 중단 MongoDB 작업 재개 |

## 검증 범위

실제 로컬 Redis 소스와 지정 Enterprise Proxy 타깃에서 자료형·TTL, 기존 키 유지, Bloom 오탐, Bloom 실패 대체, LIVE 값·TTL·삭제를 검증했습니다. 임시 MongoDB 8.0의 180개 BSON 문서를 5개 청크로 처리하고 취소 후 재개, JSON 타입 보존과 파일 정리를 확인했습니다. 다른 MongoDB/Enterprise 제품 버전·인증·TLS·Cluster·Active-Active 배포까지 검증한 결과는 아닙니다.
