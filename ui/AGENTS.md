# Prototype Instructions

## RIOTX Workbench decisions
- Preserve the compact workspace navigation and central canvas. As of 2026-10-20 the right inspector is a floating slide-out drawer, collapsed by default with a four-button rail. Desktop canvas reflows wider on close; small screens overlay the drawer. Remember open/tab state, keep child forms mounted while folded, support Escape and restore rail focus. As of 2026-10-20, default the global Theme preference to System match (OS light/dark); offer Dark override and persist the browser-wide choice. Apply semantic colors to the full app including charts, logs, drawers and modals; react to OS changes. When dark is resolved, match RedisInsight official dark theme: #121212 page, #202020 panels, #383838 borders, #8ba2ff primary, #dfe5ef text. Use Inter as the open font alternative to Graphik and Source Code Pro for code.
- Result comparison belongs under its replication in navigation, while retaining its own execution/history and immutable execution snapshots. As of 2026-10-20, child comparisons resolve connections and supported comparison options from the current parent at run submission; do not use independent child settings. QUICK/FULL/NONE is configured in the parent. Explicit parent IDs survive endpoint/workspace changes. Only infer a legacy parent when workspace and endpoint pair identify one replication unambiguously. Show unmatched comparisons independently. Never imply that equal key counts or process exit 0 guarantees full equality.
- Workspace and job rows have option menus for recoverable deletion. Parent deletion includes child comparisons; queued/active runs block deletion. Keep run history, logs, connection profiles and Redis data. Restore from the global deleted-items menu; never seed new demo jobs merely because all existing jobs are deleted.
- Settings, Logs and About are working menu tabs. LIVE source and target DB key totals stay pinned across tabs.
- Detect notify-keyspace-events independently on both endpoints. Separate observation subscriptions from deliberate server configuration changes.
- Official redis/riotx-dist stable releases are the update source. About must show included/minimum RIOTX versions and dependencies.
- Real Docker/API/RIOTX integration is explicitly authorized. Show unavailable/stale data rather than mock telemetry.

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
- As of 2026-10-20, file-import source counts come from the job's configured uploaded file and parser, labeled source input records, never from a retained Redis source ID. Keep Redis LIVE DB totals for replication. File settings expose atomic input replacement and an automatic reimport toggle; poll server-file metadata every two seconds even when automatic import is off. Browser-local originals cannot be watched after upload. Initial import is manual; later changed file versions run once, after active runs finish. Preserve immutable input versions and show unknown/unsupported counts honestly.
- As of 2026-10-20, the left sidebar execution history is an upward-opening bottom drawer, collapsed by default with its open state saved locally. Keep the handle at the viewport bottom while scrolling, show the selected job's available runs in an independently scrollable list, and open that run's logs when selected. Escape inside the drawer closes it and returns focus to its handle. On mobile use a full-width bottom drawer rather than hiding history.

- Connection management offers a per-profile options menu with explicit deletion confirmation. Keep demo profiles until explicitly deleted. Block deletion while queued/active run snapshots reference the profile; otherwise clear its connection assignments from jobs (including deleted jobs), preserve run history/logs and Redis data, and stop observation. Profile credential deletion is permanent.
